# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FastAPI backend (Spanish-language domain and code identifiers) that answers questions about the CDMX Reglamento de Tránsito using RAG with verified citations. No PyTorch: the LLM (Qwen3 via vLLM) and embeddings (bge-m3) are consumed through OpenAI-compatible APIs. See `README.md` for endpoints, deployment and configuration details.

## Commands

```bash
pip install -e ".[dev]"
pytest                                   # all tests, no network (in-memory Qdrant, hashing embeddings, fake LLM)
pytest tests/unit/test_retrieval.py::test_name   # single test
ruff check .                             # lint (line-length 110, rules E,F,I,B,UP,BLE)
python -m app.cli ingest --recrear       # index data/*.jsonl chunks into Qdrant
uvicorn app.main:app --reload --port 8080
docker compose up -d qdrant api && docker compose run --rm ingest
```

To run the flow without any servers: `RT_QDRANT__LOCATION=":memory:" RT_EMBEDDINGS__PROVIDER=hashing RT_EMBEDDINGS__DIMENSION=256 RT_LLM__PROVIDER=fake` (hashing embeddings have no semantics; test-only).

## Architecture

Ports-and-adapters layout:
- `app/domain/ports.py` defines the `Protocol`s (`EmbeddingProvider`, `SparseEncoder`, `ChunkRepository`, `ArticleRepository`, `LLMProvider`). Services depend only on these, never on Qdrant/LangChain.
- `app/infrastructure/` holds adapters; `embeddings/factory.py` and `llm/factory.py` pick the provider from config (`openai_compatible`, or `hashing`/`fake` for tests).
- `app/core/container.py` is the composition root; `app/api/dependencies.py` exposes it via FastAPI `Depends`; `create_app(settings, container)` in `app/main.py` lets tests inject fakes (see `tests/conftest.py`).
- `app/domain/referencias.py` (parses "artículo 14, fracción I, inciso a)") and `sanciones.py` (UMA → pesos) are pure rules.

Query flow (`app/services/answer.py`, `retrieval.py`, `context_builder.py`): exact-reference lookup via payload filter → hybrid search (dense + sparse, RRF fusion) → support threshold (`min_dense_score` / `min_cobertura_lexica`) → parent-article context → LLM returns JSON `{encontrado, respuesta, citas: [ids]}` → citation verification.

Invariants to preserve:
- Legal text shown to users always comes from the DB, never from LLM output; the LLM only writes a short summary.
- Citations must reference chunk ids that were in the context; otherwise the answer is discarded and "no encontré" is returned.
- Below the support threshold, return "no encontré" **without calling the LLM**; if the LLM fails, return top fragments (degraded mode).

## Configuration

Precedence: env vars > `.env` > `config/settings.yaml` > defaults. Env format `RT_<SECCION>__<CLAVE>`; secrets only in `.env`. Prompts live in `config/prompts/*.md` (editable without code changes). `uma.valor_diario` changes every Feb 1 and must be verified against INEGI.

## Data

`data/` (768 chunks, 70 articles) is generated by an external extractor (`reglamento-transito/extraer_reglamento.py`, not in this repo) from the official PDF; after replacing the files, re-run `ingest --recrear`. Changing the embedding model/dimension also requires `--recrear`.
